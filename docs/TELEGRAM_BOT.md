# JANGO Telegram Bot Integration

This integration adds a Telegram interface to the existing JANGO FastAPI/RAG backend. It reuses JANGO users, documents, the existing `query_rag()` service, and user-scoped retrieval. The bot only responds in private chats.

## Features included

- `/start` and `/help` help text
- Authenticated, one-time, 10-minute account-link code (`POST /api/telegram/link-code`)
- `/link CODE` to bind a Telegram account to an existing JANGO user
- `/ask QUESTION` or a normal text message to ask about that user's JANGO documents
- `/documents` to list up to 20 of that user's documents and ingestion status
- Telegram webhook secret verification and background processing
- Safe database migration for existing `users` tables; no user rows are deleted

## 1. Create a bot

1. Open Telegram and message `@BotFather`.
2. Run `/newbot` and follow the prompts.
3. Copy the bot token into the server environment as `TELEGRAM_BOT_TOKEN`. Never commit the token.
4. Generate a webhook secret with `python -c "import secrets; print(secrets.token_urlsafe(32))"` and set it as `TELEGRAM_WEBHOOK_SECRET`.

## 2. Configure and start JANGO locally

Add these values to your local `backend/.env` (or your existing environment configuration):

```dotenv
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_WEBHOOK_SECRET=your_random_webhook_secret
```

Install dependencies and start the existing FastAPI app using the same commands documented in the root README. No extra Python package is needed; the project already depends on `httpx`.

## 3. Configure the webhook

The public HTTPS webhook URL is: `https://YOUR-BACKEND-HOST/api/telegram/webhook`. Configure it after deploying the backend. Replace placeholders locally; do not include the token in screenshots, commits, or logs.

```bash
export TELEGRAM_BOT_TOKEN='your_bot_token'
export TELEGRAM_WEBHOOK_SECRET='your_random_webhook_secret'
curl --fail-with-body --request POST \
  --url "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  --data-urlencode 'url=https://YOUR-BACKEND-HOST/api/telegram/webhook' \
  --data-urlencode "secret_token=${TELEGRAM_WEBHOOK_SECRET}" \
  --data-urlencode 'allowed_updates=["message"]'
```

To check webhook status:

```bash
curl --fail-with-body "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getWebhookInfo"
```

For local testing, use a public HTTPS tunnel pointing to the local FastAPI port. Telegram webhooks do not call `localhost` directly. The webhook endpoint deliberately returns `503` until both Telegram settings are configured.

## 4. Link a JANGO account

1. Sign in to JANGO in the web app.
2. Make an authenticated `POST /api/telegram/link-code` request using the same JANGO bearer token as the web app. The response contains a one-time code that expires in 10 minutes.
3. Open the bot in a **private chat** and send `/link YOUR_CODE`.
4. Send `/ask Summarize my uploaded report`, or send a question as a normal message.
5. Use `/documents` to view your latest uploaded documents.

Example API request (replace the URL and token):

```bash
curl --fail-with-body --request POST \
  --url 'https://YOUR-BACKEND-HOST/api/telegram/link-code' \
  --header 'Authorization: Bearer YOUR_JANGO_ACCESS_TOKEN'
```

## Security notes

- A Telegram user ID is linked only after a valid, unexpired code generated by an authenticated JANGO user is presented. Only a SHA-256 hash of the link code is stored.
- A Telegram account can be linked to at most one JANGO account, and a JANGO account to at most one Telegram account.
- Queries call the existing RAG service with the linked JANGO user's database ID; the bot does not accept a user ID from Telegram message text.
- The bot refuses to handle messages in groups to reduce the chance of exposing private document answers.
- The webhook checks Telegram's `X-Telegram-Bot-Api-Secret-Token` header. Keep the secret private.
- This initial integration handles text Q&A and document listing. Uploading PDFs from Telegram, unlinking accounts, and webhook update deduplication are not included yet.
- The current JANGO deployment needs persistent storage and correct environment configuration for its database, uploaded PDFs, and Chroma index, just as the web interface does.
